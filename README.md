# xray-guard

Минимальная защита **Xray / 3x-ui (VLESS, TCP/443)** на основе `nftables`, журнала успешных подключений Xray и `systemd`.

**Идея:** новый IPv4-адрес получает одну попытку доступа к TCP/443 продолжительностью **5 минут**. Если за это время Xray зафиксирует успешное подключение клиента в `/usr/local/x-ui/access.log`, адрес попадёт в `trusted4` на **6 часов**. Иначе новые пакеты от него будут блокироваться до ежедневной очистки списков неизвестных IP в **04:00 UTC**.

> **Статус:** схема успешно проверена на Debian VPS: watcher обнаружил строку `accepted ... email:` и добавил адрес в `trusted4`. Полная проверка блокировки после 5 минут и сценария перезагрузки не проводилась. Это не универсальный firewall и не защита от DDoS на уровне провайдера.

## Требования

- Debian/Linux с `systemd`, `nftables` и Python 3.
- Права `root` и доступ по SSH/консоли провайдера.
- Работающий Xray под управлением 3x-ui, слушающий **TCP/443**.
- Включённый **access log** Xray в интерфейсе 3x-ui; файл `/usr/local/x-ui/access.log` должен существовать и пополняться при успешных подключениях.
- В журнале успешное подключение должно выглядеть примерно так:

  ```text
  2026/11/11 10:13:32 from 198.51.100.10:12345 accepted tcp:example.com:443 [inbound-443 -> sing-box] email: example-user
  ```

  Здесь `inbound-443` — **точное имя inbound tag**, которое ищет watcher. Если у вас другой tag, измените регулярное выражение `PATTERN` в `02-install-xray-guard.sh` до установки.

**Не покрывается:** IPv6, UDP/443, другие порты, исходящий трафик и настройки маршрутизации Xray/sing-box. Если Xray доступен по IPv6, этот фильтр не защитит IPv6-вход.

## Установка

**Внимание:** первый скрипт удаляет **все** правила в таблицах `inet xray_guard` и `inet xray_guard_test`, а также известные файлы и службы предыдущих версий. Не запускайте его, если эти имена используются для других задач. Он **не** удаляет таблицы firewall с другими именами, Xray, 3x-ui, sing-box или SSH. Между очисткой и установкой порт 443 может оказаться открыт для всех, если его не ограничивает другой firewall.

1. Склонируйте репозиторий или скопируйте оба `.sh`-файла на сервер. Проверьте их содержимое перед запуском.
2. В 3x-ui включите журнал доступа Xray и убедитесь, что в `/usr/local/x-ui/access.log` появляются **новые** строки `accepted` при подключении клиента.
3. Выполните из каталога проекта:

   ```bash
   sudo bash ./01-clean-xray-guard.sh
   sudo bash ./02-install-xray-guard.sh
   ```

   **Не запускайте очистку повторно после успешной установки**, если не хотите сбросить текущие доверенные IP и правила.

4. Переподключите VLESS-клиент **после** установки и проверьте:

   ```bash
   systemctl is-active xray-guard.service xray-trust-watch.service
   journalctl -u xray-trust-watch.service -n 30 --no-pager
   nft list set inet xray_guard trusted4
   systemctl list-timers --all | grep xray-guard
   ```

Ожидаемое сообщение watcher: `Trusted <IPv4> for 6h`. Установщик **не** доверяет IP из старых строк журнала: отслеживаются только новые записи после запуска.

## Как устроены списки

| Набор nftables | Значение |
|---|---|
| `pending4` | Адреса с активным пробным окном (тайм-аут 5 минут) |
| `seen4` | Адреса, которым уже предоставлялось пробное окно в текущем цикле очистки |
| `trusted4` | Адреса, для которых watcher увидел успешное подключение Xray (`accepted`, `inbound-443`, `email`) — тайм-аут 6 часов |
| `unknown_connections4` | Служебный набор для ограничения одновременных соединений неизвестных IP |

Для недоверенных адресов дополнительно действуют ограничения: не более **60** одновременно отслеживаемых соединений и скорость новых соединений **15/с** с burst **40**. Доверенные адреса обходят *только* ограничения этой таблицы, но не другие правила firewall.

В `pending4` может быть много адресов — это **не** список авторизованных клиентов. После пяти минут адрес исчезает из `pending4`, но остаётся в `seen4`, поэтому повторного пробного окна до очистки не получает.

**Срок доверия:** 6 часов с последнего обновления watcher. При новых успешных записях для IP срок может обновляться (скрипт ограничивает частоту обращений к nftables). Если доверие истечёт, а IP уже есть в `seen4` и не в `pending4`, он будет блокироваться до ежедневной очистки — учитывайте это для редко переподключающихся клиентов.

## Ежедневная очистка и диагностика

Очистка `seen4`, `pending4` и `unknown_connections4` выполняется в **04:00 UTC**; `trusted4` сохраняется. Для внепланового сброса пробных/заблокированных IP:

```bash
sudo systemctl start xray-guard-cleanup.service
```

Проверить состояние и счётчики:

```bash
sudo nft list set inet xray_guard pending4
sudo nft list set inet xray_guard seen4
sudo nft list set inet xray_guard trusted4
sudo nft -a list chain inet xray_guard check443_v4
sudo journalctl -fu xray-trust-watch.service
sudo tail -f /usr/local/x-ui/access.log
```

Если `trusted4` пуст, проверьте наличие **новых** записей в access log, совпадение `inbound-443`, поле `email` и права доступа watcher. Если клиенты перестали подключаться, можно сбросить временные списки командой выше; это не добавляет IP в доверенные.

## Какие файлы создаются

- `/root/xray-guard.nft`
- `/usr/local/sbin/xray-guard-load.sh`
- `/usr/local/sbin/xray-guard-cleanup.sh`
- `/usr/local/bin/xray-trust-watch.py`
- `/etc/systemd/system/xray-guard.service`
- `/etc/systemd/system/xray-trust-watch.service`
- `/etc/systemd/system/xray-guard-cleanup.service`
- `/etc/systemd/system/xray-guard-cleanup.timer`

Журнал `/usr/local/x-ui/access.log` и системные журналы **не удаляются**. Настройка access log выполняется пользователем через интерфейс 3x-ui.

## Удаление

```bash
sudo bash ./01-clean-xray-guard.sh
```

После удаления фильтра `xray-guard` порт TCP/443 будет обрабатываться оставшимися правилами firewall; это может означать полный доступ извне.

## Ограничения и безопасность

- Это **IPv4 TCP-only** решение. IPv6 требует отдельных правил.
- IP определяется по тексту `access.log`; журнал должен быть доступен на запись только доверенным процессам. Это не криптографическое подтверждение личности IP самим nftables.
- При перезагрузке и пересоздании таблицы динамические списки IP теряются. Watcher читает **только новые строки**, поэтому клиенту потребуется новое успешное подключение.
- `seen4` ограничен 65 535 адресами; при очень интенсивном сканировании возможны проблемы с ёмкостью наборов и нагрузкой.
- Существующие TCP-соединения могут сохраняться после истечения пробного окна: фильтр прежде всего ограничивает новые попытки, а не принудительно разрывает все ранее установленные соединения.
- Скрипты рассчитаны на конкретную схему Xray и требуют тестирования в вашем окружении. Держите доступ к консоли провайдера на случай ошибок.
